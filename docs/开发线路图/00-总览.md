## 1. 任务拆解与验证的总原则

**验证金字塔**（每个任务三层都要过，缺一不算完成）：

| 层 | 手段 | 约定 |
|---|---|---|
| L1 单元测试 | vitest | 用例名必须带流程图「情况编号」，如 `it("情况2 验证码过期→提示重发")`，**一个情况至少一个用例**，与流程图逐一核对不遗漏 |
| L2 集成测试 | vitest + docker compose 真实依赖 | 跑真实 MySQL/Redis/Kafka/模拟链，验证模块拼接（幂等落库、消息流转） |
| L3 端到端演练 | `scripts/verify/*.sh` 可重复执行的脚本 | 按用户旅程走全流程，输出每步的 HTTP 状态与断言结果 |

**任务完成（DoD）四件套**：① L1/L2 测试全绿 ② `pnpm lint && pnpm typecheck && pnpm build` 通过 ③ CI 在 main 上绿 ④ 对应明细文档状态列更新。

**分支覆盖红线**：账务、撮合、提现三个资金相关模块，L1 用例必须覆盖流程图标注的**全部**情况编号；其他模块 ≥ 全部正常分支 + 主要异常分支。

**状态标记**：⬜ 未开始 ｜ 🔧 进行中 ｜ ✅ 完成（含日期）

## 3. 关键工程决策（跨里程碑生效）

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 1 | 金额精度 | 一律 BigInt 最小单位，禁止 float | 资损红线，《技术决策方案》§精度 |
| 2 | 邮件（M1 期间） | 先写 outbox 表（可查不发），M2 接真实 SMTP | 内部阶段无真实用户，但「该发邮件」必须可断言 |
| 3 | 链上测试环境 | EVM 用 **Anvil 本地链**（可模拟出块/重组）；TRON 用 mock TronGrid | 不依赖第三方、可复现链重组（流程图 2.1 情况5） |
| 4 | 首发配置 | USDT-TRC20 + 一条 EVM 链；交易对 BTC/ETH/SOL×USDT；费率 0.1%/0.1% | MVP 文档 §12 拍板建议；币种=钱包支持=交易对三者联动 |
| 5 | KYC 前置 stub | M1 内部账户直接种 KYC1 状态，校验逻辑照写 | M2 接 KYC 流程后业务代码零改动 |
| 6 | 撮合持久化 | M1/M2 进程重启=挂单全撤重来；WAL+快照恢复在 M3 | 健壮性后置是既定策略 |
| 7 | Admin 入口（M1 期间） | 纯 API + 脚本，无页面；页面在 M2 | 双人复核、审计日志逻辑先做全 |
