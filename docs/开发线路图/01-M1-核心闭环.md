# M1 · 核心闭环（内部）— 任务明细

> 总览见 [00-总览.md](00-总览.md)。**M1 目标**：内部全流程跑通「注册 → 充值(模拟链) → 现货买卖 → 提现(人工审核) → 日终对账平」。
> 退出标准：`scripts/verify/m1-full-journey.sh` 全绿 + **日终对账连续 7 天平**。

依赖顺序即编号顺序：T1 账务是所有资金操作的地基 → T2 账户 → T3 配置 → T4 下单前置 → T5 撮合撤单 → T6 行情 → T7 充值 → T8 提现 → T9 对账 → T10 E2E。

## T1 账务统一入口 ✅（2026-09-14 完成，实际晚于 T2）

| 项 | 内容 |
|---|---|
| 依据 | 流程图 **5.1**（幂等→余额校验→原子变更→不可变流水） |
| 交付 | 账务模块：`credit / debit / freeze / unfreeze / reversal` 五操作；幂等单号必填；流水含余额快照；差错只增冲正不改原流水 |
| 涉及表 | Asset / AssetFlow（UNIQUE(bizNo) 幂等兜底） |
| 实施记录 | 见 [../实际开发图/02-M1-核心闭环.md](../实际开发图/02-M1-核心闭环.md) §1.1~§1.5 与时序图 06 第 8 图。落点 `apps/api/src/ledger/`；五操作统一走 `LedgerService.apply/reverse`，T5/T7/T8 注入复用不走 HTTP。验证：L1 12/12 + L2 真实 MySQL 并发 4/4（`RUN_DB_TESTS=1` 门控，20 线程同 UID 余额精确、同单号只记 1 笔、抢冻结 8 成 12 拒）+ L3 `scripts/verify/ledger.sh` 9/9 + 四件套绿 |
| 偏差 | ① AssetFlow 由单快照（delta/balanceAfter）升级为**双级快照**（availDelta/frozenDelta 带符号 + Before/After 四快照），对账恒等式 SUM(availDelta)==available 直连 T9 ② 冻结后扣款用 DEBIT+fromFrozen 表达，未加第六操作 ③ 防死锁采用「事务外建户 + 事务内单点行锁」结构，并覆盖 raw SQL 死锁的 P2010(1213) 重试（细节见实际文档 §1.5） |

**验证方法**：
- L1：`幂等单号重复→返回原结果不重复记账`、`余额不足→拒绝且无任何写入`、`冻结→可用减冻结增总额不变`、`冲正→生成反向流水且原流水不可变`
- L2：真实 MySQL 并发 20 线程同 UID 打款，断言最终余额精确、bizNo 无重复
- L3：`scripts/verify/ledger.sh`——入账 100 USDT → 冻结 30 → 查询返回 `{available: 70000000, frozen: 30000000}`（最小单位）
