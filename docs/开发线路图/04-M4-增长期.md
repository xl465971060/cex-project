# M4 · 增长期 — 任务明细

> 总览见 [00-总览.md](00-总览.md)。**M4 目标**：在稳定运行的底盘上做增长功能。
> 退出标准：按功能各自验收；无统一单一指标（进入本里程碑时再细化）。

前置：M3 关闭（监控+自动审核就位，放量有护栏）。M4 各任务相对独立，可按业务优先级调整顺序；进入时把方向级描述细化到 M1 明细的粒度（任务+验证）。

---

## M4-1 OpenAPI（交易）+ 子账户 ⬜（预估 8 天）

| 项 | 内容 |
|---|---|
| 依据 | MVP 文档延后项16/23（M3 只读 → M4 交易） |
| 交付 | 交易端点（下单/撤单/批量查询，HMAC 签名+限频）；子账户体系（主子账户、资产划转、独立 API Key）；做市商友好：batch 接口+更高限频档 |
| 验证 | 签名/重放攻击用例（nonce/timestamp 窗口）；子账户与主账户额度隔离断言；压测通过 M3 的监控看板观察 |

## M4-2 邀请返佣结算 ⬜（预估 5 天）

| 项 | 内容 |
|---|---|
| 依据 | MVP 文档延后项15（M1 注册已埋邀请关系，只记不结） |
| 交付 | 返佣规则配置（比例/层级/币种）；按成交手续费定时结算入账（走 T1 账务，幂等单号=结算周期+邀请关系）；返佣报表 |
| 验证 | L1 规则边界（层级上限/比例变更生效时点）；L2 结算重跑不重复（幂等）；对账把返佣纳入查1 |

## M4-3 Convert 一键兑换 ⬜（预估 5 天）

| 项 | 内容 |
|---|---|
| 依据 | MVP 文档模块7（延后 M3/M4，§11 归 M4） |
| 交付 | 报价（基于盘口+点差）→锁定报价 15s→内部拆成两笔市价单执行→差额即平台收益；滑点保护 |
| 验证 | L2 报价与实际成交偏差≤配置点差；执行失败→全额回滚不吞钱；并发同用户重复点击→幂等 |

## M4-4 新币上线标准化流程（SOP）⬜（预估 3 天）

| 项 | 内容 |
|---|---|
| 依据 | MVP 文档 §2 联动原则（币种=钱包支持=交易对三者联动） |
| 交付 | 上币 checklist 工具化：链/币种配置→钱包地址派生→扫块就绪自检→交易对配置→行情初始化→公告，一键式脚本+页面；自检不过禁止上架 |
| 验证 | 用一个新测试币走完整 SOP→全程无手工 SQL；故意漏配确认数→自检拦截 |

## M4-5 法币快捷买币（PSP）⬜（预估 8 天，含供应商谈判周期）

| 项 | 内容 |
|---|---|
| 依据 | MVP 文档模块8（延后，§11 归 M4；拒付/合规风险需供应商） |
| 交付 | PSP 供应商接入（抽象接口）：下单→跳转支付→回调入金（走充值入账链路，幂等单号=PSP订单号）；拒付风控：新账户限额、回调验签、对账纳入 PSP 渠道 |
| 验证 | L2 mock PSP：成功/失败/重复回调/伪造签名四类用例；对账查2 扩展 PSP 渠道余额勾稽 |
