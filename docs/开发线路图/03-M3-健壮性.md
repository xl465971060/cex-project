# M3 · 健壮性 — 任务明细

> 总览见 [00-总览.md](00-总览.md)。**M3 目标**：把「人工兜底」换成「自动+可观测」，为放量做准备。
> 退出标准：提现自动通过率 >80% 且人工抽检无误判；核心服务有监控告警覆盖。

前置：M2 关闭（真链小额零资损）。任务间无严格串行依赖，按编号顺序做即可；M3-1 建议最先（其他任务的告警都挂在监控上）。

---

## M3-1 监控告警体系 ⬜（预估 5 天）

| 项 | 内容 |
|---|---|
| 交付 | Prometheus + Grafana（docker compose 加服务）；各服务 `/metrics`：QPS/延迟/错误率、撮合队列深度、Kafka 消费滞后、钱包扫块滞后、对账结果、热钱包余额；告警规则→运营群 |
| 验证 | Grafana 面板能看到全链路指标；人为打挂一个服务→5 分钟内收到告警（用测试群/邮件断言） |

## M3-2 撮合引擎恢复（WAL + 快照）⬜（预估 5 天）

| 项 | 内容 |
|---|---|
| 依据 | 总览决策 #6（M1/M2 重启=挂单全撤，M3 补齐） |
| 交付 | 订单事件先写 WAL 再入内存簿；定期快照；重启后 快照+WAL 重放恢复到崩溃前状态；恢复期间拒新单并公告 |
| 验证 | L2：压测中 kill -9 撮合进程→重启→订单簿与账务冻结量逐笔核对一致；注入「WAL 尾部截断」损坏→能回退到上一致快照 |

## M3-3 提现自动审核（规则引擎）⬜（预估 5 天）

| 项 | 内容 |
|---|---|
| 依据 | 流程图 4.2 的人工核对清单规则化；MVP 文档 §6 情况15 |
| 交付 | 规则引擎：KYC等级/注册时长/历史行为/地址白名单/金额档位→自动通过(小额)/自动驳回(命中黑规则)/转人工；规则在配置中心可视化管理；每次自动决策留审计 |
| 验证 | L1 规则逐条命中/不命中；L2 与人工审核并行灰度跑 1 周比对结论；退出标准挂钩：自动通过率 >80% 且抽检无误判 |

## M3-4 AML 供应商接入 ⬜（预估 3 天）

| 项 | 内容 |
|---|---|
| 依据 | MVP 文档 §6 情况16、§10 |
| 交付 | Chainalysis/MistTrack 类 API 接入（抽象供应商接口）；提现审核清单第②项由人工查询变为自动风险评分；充值侧对入金地址做风险标记 |

## M3-5 自动打款与热钱包自动补币 ⬜（预估 4 天）

| 项 | 内容 |
|---|---|
| 依据 | 流程图 4.2 情况10（人工补币 → 自动化） |
| 交付 | 自动打款：自动审核通过的提现由热钱包直接签名广播（限额内）；热钱包余额低于水位→自动从冷钱包归集账户补币（冷钱包操作仍人工确认，自动只做「提醒+预备交易」）；归集脚本（MVP 文档延后项11） |
| 验证 | L2 Anvil：水位触发→预备交易生成→人工确认→到账；全程审计与告警 |
