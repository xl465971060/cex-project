## 5. 反向代理 Nginx（⏳ 随生产编排提供，不在本机单独安装）

开发期由 Next.js/NestJS 自身端口直连，无需 Nginx。生产在 `infra/docker-compose.prod.yml` 中以容器提供：

```yaml
# 生产编排片段（M1 上线时落地）
nginx:
  image: nginx:1.27-alpine
  ports: ["80:80", "443:443"]
  volumes:
    - ./nginx/conf.d:/etc/nginx/conf.d:ro
    - ./certs:/etc/nginx/certs:ro   # TLS 证书（或交给 Cloudflare 源站证书）
```

## 7. 监控告警栈（⏳ M2 接入，容器方式）

模板（届时新增 `infra/docker-compose.monitoring.yml`）：

```yaml
services:
  prometheus:
    image: prom/prometheus:v3.x
    ports: ["9090:9090"]
    volumes: ["./prometheus:/etc/prometheus"]
  grafana:
    image: grafana/grafana:11.x
    ports: ["3001:3000"]
  alertmanager:
    image: prom/alertmanager:v0.27.x
    ports: ["9093:9093"]
  loki:
    image: grafana/loki:3.x
    ports: ["3100:3100"]
  promtail:
    image: grafana/promtail:3.x
    volumes: ["/var/log:/var/log:ro"]
```

> 注意：Alertmanager 容器端口 9093 与 Kafka controller 端口无冲突（一个走宿主机映射一个仅容器内网）。

## 10. 前后端脚手架初始化（下一步开工命令）

> 环境就绪后，按《技术决策方案》§3.1 的 monorepo 结构初始化：

```bash
# 1) workspace 根
pnpm init && pnpm add -D -w turbo typescript
mkdir apps packages

# 2) 用户端前端
pnpm create next-app@latest apps/web --ts --app --tailwind --eslint

# 3) 后端业务单体
pnpm dlx @nestjs/cli new apps/api --package-manager pnpm --strict

# 4) 撮合 / 钱包 / WS 网关（复用 NestJS 或纯 TS 进程模板，从 api 复制裁剪）
# 5) Admin 后台
pnpm create next-app@latest apps/admin --ts --app --eslint
cd apps/admin && pnpm add antd

# 6) 共享包与 ORM
mkdir -p packages/shared packages/db
cd packages/db && pnpm init && pnpm add -D prisma && pnpm add @prisma/client
pnpm prisma init --datasource-provider mysql
# DATABASE_URL="mysql://cex:cex_dev_123@localhost:3306/cex"
```
