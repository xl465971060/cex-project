### 2.3 每个文件写了什么（按这个顺序开发即可）

> 开发顺序 = 依赖顺序：先定校验规则和表 → 再做地基（错误格式/连接）→ 再做纯函数（TOTP）→ 再做验证码/邮件 → 最后组装业务逻辑和路由。

**① 共享校验规则 `packages/shared/src/schemas.ts`**
- 抽出 `passwordRule`（≥8 位、含字母、含数字），注册和重置密码共用，保证两处规则永远一致
- 新增 `registerConfirmSchema`（email+code）、`loginSchema`（email/password/totpCode?）、`forgotPasswordSchema`、`resetPasswordSchema`
- 放 shared 的原因：web 前端将来做表单时 import 同一条规则做即时提示；但后端不信任前端，收到请求仍会重新校验一遍

**② 错误与工具（3 个小文件）**
- `apps/api/src/auth/errors.ts`：`apiError(状态码, 业务码, 中文提示)` 抛 NestJS 的 HttpException。业务码（如 `EMAIL_EXISTS`）给前端分支用，中文提示直接展示给用户
- `apps/api/src/zod.util.ts`：`parseOrThrow(schema, body)` —— zod 校验不通过就抛 400 `VALIDATION`，取第一条错误文案。每个接口开头调用一次，此后代码里 `dto.email` 一定是合法邮箱
- `apps/api/src/redis.service.ts`：ioredis 客户端单例（验证码、频控、锁定计数都在 Redis），进程退出时优雅断开

**③ `apps/api/src/prisma.module.ts`**：`@Global()` 全局模块导出 PrismaService，之后任何业务模块（auth、订单…）直接构造器注入即可，不用每个模块重复声明

**④ 纯函数 `apps/api/src/auth/totp.ts`（2FA 动态码）**
- `base32Decode/base32Encode`：密钥的文本编码（Google Authenticator 扫码用的就是 base32）
- `totpAt(密钥, 时间戳)`：当前 6 位动态码 = 对「时间步计数器 = 秒/30」做 HMAC-SHA1 后动态截断取模
- `totpVerify`：允许 ±1 步（±30 秒）时钟偏差
- 不用第三方库的原因：核心就 20 行，且能用 **RFC 6238 官方测试向量**锚定正确性（官方给定密钥和时刻，断言输出必须是 287082）

**⑤ 验证码 `apps/api/src/auth/code.service.ts`（注册/重置共用）**
- 先定义 `CodeStore` 接口（get/setEx/incr/setNxEx/del 五个方法），再写 Redis 实现 —— **依赖倒置**：业务代码只认接口，单测塞一个内存 Map 实现就能跑，不用起 Redis
- `send`：60 秒重发锁（setNxEx）→ 当日计数（incr，>10 拒绝）→ 生成 6 位随机码存 600 秒
- `verify`：错码计数 ≥5 → 锁 30 分钟（就算之后输对也拒）→ 码不存在=过期 → 码对=删除并清错误计数
- Redis 键名约定 `vc:{场景}:{用途}:{邮箱}`，如 `vc:reg:code:t1@test.local`

**⑥ 邮件 `apps/api/src/auth/mail.service.ts`**：`send(uid, to, type, payload)` 只做一件事 —— 往 MailLog 插一行。M2-5 接 SMTP 时把「落库」升级成「落库+真发」，调用方一行不改

**⑦ 会话守卫 `apps/api/src/auth/jwt.guard.ts`**
- 取 `Authorization: Bearer xxx` → 验签 → 拿 UserSecurity.tokenVersion 和 JWT 里的 ver 比对 → 不一致抛 401 `SESSION_EXPIRED`（重置密码后旧登录全失效就是靠这一步）→ 通过则把 `req.user = { uid }` 传给业务

**⑧ 业务主逻辑 `apps/api/src/auth/auth.service.ts`（核心，5 个方法）**
- `registerInit`：校验 → 地区黑名单 → 邮箱查重（已注册 409）→ 邀请码校验（**无效不阻断**，置空继续）→ 发码+落邮件 → 把「密码哈希+邀请人+地区」存 Redis pending 键（600 秒）
- `registerConfirm`：验码 → 读 pending → 再查重一次（两人同时注册同一邮箱的并发兜底）→ **一个事务**里建 User + UserSecurity → 发欢迎邮件
- `login`：锁定期检查 → bcrypt 比对密码（失败计数，5 次锁 30 分钟；**邮箱不存在也是同一句「邮箱或密码错误」**，防撞库）→ 冻结账号 403 → 开了 2FA 就必须带对动态码 → 查 SecurityEvent 判断新设备（新=记 NEW_DEVICE 事件+发提醒邮件）→ 记 LOGIN 事件 → 清失败计数 → 签发 JWT `{sub: uid, ver: tokenVersion}`
- `forgotPassword`：邮箱不存在**也返回同样的成功文案**（不告诉攻击者哪些邮箱注册过），只是不发码
- `resetPassword`：验码 → 事务：更新密码哈希 + tokenVersion+1 + forbiddenUntil=now+24h → 记 PASSWORD_CHANGED 事件 + 发提醒邮件

**⑨ 路由 `apps/api/src/auth/auth.controller.ts`**：6 个端点 —— `POST /auth/register/init`、`/auth/register/confirm`、`/auth/login`、`/auth/password/forgot`、`/auth/password/reset`、`GET /auth/me`（挂 JwtGuard）。`metaOf()` 从请求头提取 ip（x-forwarded-for）/UA/地区供业务用

**⑩ 装配 `apps/api/src/auth/auth.module.ts` + `app.module.ts`**：JwtModule 用 `process.env.JWT_SECRET`、有效期 7 天；RedisCodeStore/CodeService 需要传参构造，用 `useFactory` 手工装配；app.module 的 imports 里加 `PrismaModule, AuthModule`

### 2.4 每个功能怎么单独验证（起服务后逐步 curl）

> 起服务：`pnpm --filter @cex/api dev`（等日志出现 listening on :4000）。下面每条命令都标了「应该看到什么」，不符合就是实现有问题。

**注册（流程图 1.1）**
```bash
# a. 弱密码 → 应返回 400 {"code":"VALIDATION"}
curl -s -w "\n[%{http_code}]\n" -X POST localhost:4000/auth/register/init \
  -H 'Content-Type: application/json' -d '{"email":"t1@test.local","password":"123"}'

# b. 正常发码 → 应返回 200/201 + "验证码已发送"
curl -s -w "\n[%{http_code}]\n" -X POST localhost:4000/auth/register/init \
  -H 'Content-Type: application/json' -d '{"email":"t1@test.local","password":"Abcd1234"}'

# c. 频控：60 秒内再发一次 → 应返回 429 {"code":"CODE_TOO_FREQUENT"}
curl -s -X POST localhost:4000/auth/register/init \
  -H 'Content-Type: application/json' -d '{"email":"t1@test.local","password":"Abcd1234"}'

# d. 从 outbox 读出验证码（应打印 6 位数字）
docker exec cex-mysql mysql -ucex -pcex_dev_123 -N -s cex \
  -e "SELECT JSON_EXTRACT(payload,'$.code') FROM MailLog WHERE \`to\`='t1@test.local' ORDER BY id DESC LIMIT 1"

# e. 错码 → 400 CODE_WRONG；连错 5 次 → 423 CODE_LOCKED
curl -s -w "\n[%{http_code}]\n" -X POST localhost:4000/auth/register/confirm \
  -H 'Content-Type: application/json' -d '{"email":"t1@test.local","code":"000000"}'

# f. 正确码 → 应返回 201 {"uid":"...","email":"..."}，User 表多一行
curl -s -w "\n[%{http_code}]\n" -X POST localhost:4000/auth/register/confirm \
  -H 'Content-Type: application/json' -d '{"email":"t1@test.local","code":"<d步读到的码>"}'
```

**登录（流程图 1.2）**
```bash
# a. 错密码 → 401 {"code":"INVALID_CREDENTIALS"}；不存在的邮箱也是同样文案
curl -s -w "\n[%{http_code}]\n" -X POST localhost:4000/auth/login \
  -H 'Content-Type: application/json' -d '{"email":"t1@test.local","password":"Wrong999"}'

# b. 对密码 → 200 {"token":"eyJ...","user":{...}}，把 token 存下来
curl -s -X POST localhost:4000/auth/login \
  -H 'Content-Type: application/json' -d '{"email":"t1@test.local","password":"Abcd1234"}'

# c. token 鉴权：不带 token 访问 /auth/me → 401；带上 → 200 返回当前用户
curl -s -w "\n[%{http_code}]\n" localhost:4000/auth/me
curl -s -w "\n[%{http_code}]\n" localhost:4000/auth/me -H "Authorization: Bearer <b步的token>"
# d. 新设备邮件：同一 ip+浏览器第一次登录后，MailLog 应多一条 type=NEW_DEVICE
```

**忘记密码（流程图 1.3）**
```bash
# a. 不存在的邮箱也返回 200 + 同样文案（防枚举），且 MailLog 没有新记录
curl -s -X POST localhost:4000/auth/password/forgot \
  -H 'Content-Type: application/json' -d '{"email":"nobody@test.local"}'

# b. 存在的邮箱 → MailLog 出现 type=RESET_CODE，读出重置码（同注册 d 步）
# c. 重置 → 200；旧 token 立即失效；新密码可登录
curl -s -w "\n[%{http_code}]\n" -X POST localhost:4000/auth/password/reset \
  -H 'Content-Type: application/json' \
  -d '{"email":"t1@test.local","code":"<重置码>","newPassword":"New56789"}'
curl -s -w "\n[%{http_code}]\n" localhost:4000/auth/me -H "Authorization: Bearer <旧token>"   # 应 401 SESSION_EXPIRED
curl -s -X POST localhost:4000/auth/login \
  -H 'Content-Type: application/json' -d '{"email":"t1@test.local","password":"New56789"}'   # 应 200
# d. 数据库核对：UserSecurity.forbiddenUntil 应 = 重置时刻 + 24h（禁提红线）
```

### 2.5 新手避坑（本次真实踩过的 6 个坑）

1. **dev 用 tsx 起服务会全盘崩**：Nest 靠「装饰器元数据」知道构造器参数是什么来注入依赖，tsx（esbuild）不生成这个元数据 → 报 `Nest can't resolve dependencies`。api 的 dev 改用 `ts-node --transpile-only`（真实 tsc 转换）。matcher/wallet/ws-gateway 不用 Nest，继续 tsx 没问题
2. **Prisma 访问器名 ≠ 关系字段名**：模型叫 `UserSecurity`，代码里写 `prisma.userSecurity`；`include: { security: true }` 里的 security 是 User 上关系字段的名字，两回事
3. **用到的包必须显式声明**：api 直接 import 了 zod，就必须 `pnpm --filter @cex/api add zod`。pnpm 严格 node_modules，不能「恰好装了就用」（本地能跑 CI 报错，因为提升路径不同）
4. **bash 的 `UID` 是只读内建变量**，脚本里赋值直接报错，换成 `NEW_UID`
5. **`VAR=$(func)` 是子 shell**：func 里 `CODE=$(curl ...)` 设置的变量带不回父 shell，验证脚本断言全拿到旧值。解法：把响应码写到临时文件再 cat
6. **CI 是全新环境**：本地能跑不代表 CI 能跑。本项目踩过 `prisma generate`（@prisma/client 要先生成才有 PrismaClient 类型）——已在 ci.yml 的 install 之后补了显式 generate 步骤
